# CURRENT_STATE

*Актуализировать при любых значимых изменениях кода или инфраструктуры.*

## Структура репозитория

- **Frontend:** корень (`package.json`, `vite.config.ts`, `src/`).
- **Backend:** `server/` (отдельный `package.json`, `server/Dockerfile`, `server/src/`).
- **Docker:** корневой `Dockerfile` (nginx + собранный SPA), `docker-compose.yml` (postgres + api + web).
- **Скрипты деплоя:** в корне есть `deploy.ps1` и множество markdown-инструкций (не входят в AI-память по содержанию, только факт наличия).

## Сборка и скрипты

### Корень (frontend)

- `npm run dev` — `npx vite`
- `npm run build` — **`vitest run`** затем **`npx vite build`**
- `npm run test` — **`vitest run`**
- `npm run lint` — ESLint по `.js,.jsx,.ts,.tsx`
- `npm run preview` — `npx vite preview`

### Backend (`server/`)

- `npm run dev` — `node --watch src/index.js`
- `npm run start` — `node src/index.js`

## Тесты

- **Vitest** подключён; один файл **`src/constants/routeSeo.test.ts`** проверяет полноту **`SEO_BY_PAGE`** для всех ключей страниц из **`App.tsx`**.

## SEO и статика

- **`public/robots.txt`** — правило для основных краулеров и части ботов ИИ; `Disallow: /api/`; ссылка на sitemap **https://voensovet.ru/sitemap.xml**.
- **`public/sitemap.xml`** — основные hash-URL разделов (без личного кабинета, админки и OAuth callback).
- **`index.html`**: язык **`ru`**, базовые `meta description`, `keywords`, canonical **`https://voensovet.ru/`**, Open Graph и Twitter Card (fallback без выполнения JS).
- **Клиент:** **`src/constants/site.ts`** — `SITE_ORIGIN` из **`VITE_SITE_URL`** или **`https://voensovet.ru`**.
- **`src/constants/routeSeo.ts`** — `title`, `description`, `keywords`, `hash`, `noindex` для каждого ключа **`currentPage`**.
- **`AppRouteSEO`** в **`App.tsx`** синхронизирует мета-теги с активным маршрутом; **`SEO.tsx`** дополняет OG/Twitter, **`rel="canonical"`**, **`hreflang="ru"`**, JSON-LD (**Organization**, **WebSite**, **WebPage**).
- **Яндекс.Метрика:** счётчик удалён из **`index.html`** ради приватности форм и вопросов; сторонний скрипт записи действий не загружается.

## Реализованные возможности (по наличию страниц и API-клиента)

- Страницы SPA (hash-маршруты в `App.tsx`): приветственный вход, домашняя, помощь, контрактная служба, разделы veteran/family/bereaved/benefits/complaints/organizations/return, профиль, админка, OAuth callback.
- Добавлен мобильный прототип `#navigator`: вопрос определяется простыми локальными правилами; шесть крупных плашек выбирают тему, в том числе своё дело и строительство дома. Работа, обучение, жильё и выплаты пока представлены демонстрационными шагами. По бизнесу и дому показаны четыре карточки с официальными источниками, условиями, документами, ведомством и сроками. Анкета и история маршрута ещё не реализованы.
- В прототипе можно выбрать одну из четырёх целевых групп: ветеран с удостоверением, участник при оформлении статуса, член семьи, семья погибшего. Группа фильтрует карточки с условиями по аудитории, но не подтверждает право на меру; демонстрационные шаги остаются общими.
- Добавлен серверный каталог `benefit_measures` и вкладка «Меры поддержки» в существующей админке. Администратор может создавать и редактировать черновики, публиковать заполненные карточки и снимать их с публикации. Публичный API возвращает только опубликованные карточки с федеральным или выбранным региональным охватом; мера, ограниченная населённым пунктом, скрыта без его явного выбора. Каталог пока пуст и не связан с экраном проводника; четыре прежние карточки остаются в локальном прототипе до этапа наполнения.
- UI-компоненты: шапка/подвал, регион, AI-ассистент с Markdown, формы входа/регистрации, карточки организаций и др.
- Клиентский модуль `api` покрывает auth, профиль, заявки/визиты страниц, админ-настройки и статистику, историю и обработку AI.

## Замечания по коду (наблюдаемые)

- **`react-router-dom`** указан в зависимостях, но импортов из этого пакета в `src/` не обнаружено.
- Регион выбирается вручную без IP-геолокации. При регистрации он сохраняется в `users.region_id`; после входа берётся из учётной записи, смена региона сохраняется через API профиля. Для прежних аккаунтов без региона предлагается выбор. По умолчанию доступны Владимирская и Калужская области; администратор может включить другие регионы во вкладке «Регионы». Это не добавляет для них меры поддержки.
- AI-маршрут теперь отправляет внешнему сервису только фиксированный общий вопрос по локально определённой теме, регион из профиля для пилотных областей и случайный ID обращения. Исходный текст и данные профиля не включаются в запрос к AI; исходный вопрос и ответы по-прежнему хранятся в `ai_requests` на сервере для истории пользователя и доступны администратору через существующий раздел. Содержимое вопроса и контакты убраны из затронутых серверных и браузерных логов; общий обработчик ошибок не отдаёт stack trace клиенту. Прототип проводника не использует внешний AI.
- **Ограничение:** ответ существующего AI-помощника теперь общий по теме и может не учитывать подробности свободного вопроса. Исторические записи `ai_requests` не очищались; отдельные правила доступа, хранения и удаления данных ещё предстоит определить. Вход через Yandex OAuth остаётся внешней интеграцией по выбору пользователя.
- `npx tsc --noEmit` обнаруживает ранее существующие ошибки типов в других модулях. `npm run build` запускает тесты и Vite, но не TypeScript typecheck.
- Старая `BenefitsPage` содержит статические сведения, включая сумму за 2024 год и старые названия ведомств; их нельзя автоматически использовать как проверенный каталог проводника.

## Vite build

- В **`vite.config.ts`** имена выходных chunk/asset файлов включают **`Date.now()`** для смены хэша при каждой сборке.
- `npm run build` запускает тесты перед сборкой Vite; `src/data/navigator.test.ts` проверяет целевые группы, региональный и групповой отбор, наличие сведений в карточках подтверждённых механизмов и разбор запросов. Серверные тесты проверяют список включённых регионов и регистрацию с выбранным регионом.
- Тесты каталога проверяют валидацию черновика и публикации, администраторский доступ, скрытие черновиков, региональный/городской отбор и возврат изменённой карточки в черновик.
